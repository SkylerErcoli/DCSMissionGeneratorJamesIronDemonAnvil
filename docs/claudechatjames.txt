I’ve written Operation Iron Anvil, a 2-ship Hornet co-op strike mission. It’s a Lua script, iron_anvil.lua, that you load into the Mission Editor, so you build the units yourself and the script drives the mission logic. I haven’t run it in DCS, so expect to fix a typo or two on the first test.

The mission

SEAD: destroy the SAM site (75% of its units by default).
Strike: destroy three ground targets.
Reaction: the first target hit scrambles enemy fighters, and finishing both objectives scrambles a second wave.
RTB: you win when every surviving Hornet lands at the home base. You lose if the whole flight is dead.
F10 menu (per flight): mission status, bearing and range to the nearest target (magnetic and true), a smoke mark on it (3 per flight), and a vector home. Everyone also gets a briefing when they spawn, and the debrief shows kills per player.
Mission Editor setup (Caucasus)

Place one blue group of 2x F/A-18C, skill Client, starting from Batumi (or Kobuleti).
Place a red SAM group named RED SAM (SA-6 or SA-11, plus some AAA) near the targets.
Place three red ground units or statics and rename them TGT-1, TGT-2 and TGT-3.
Place two late-activated red fighter groups named RED CAP 1 and RED CAP 2 (MiG-29s or Su-27s), each with a route toward the target area.
Add a trigger: type ONCE, condition TIME MORE 5, action DO SCRIPT FILE, and pick iron_anvil.lua.
If you use different names, change them in the CFG table at the top of the script. The header comment in the file repeats these steps.

Things to know

If a flight member sits cold on the ramp, they block the win until they land, since every pilot who joined has to be down.
The script sets a flag called IRON_ANVIL_RESULT (1 = win, 2 = lose). You can hook a trigger to it if you want the mission to end or play a sound.
Errors and missing group names are written to dcs.log with the prefix IRON ANVIL, so check there if something doesn’t trigger.
I can also add a tanker, a mid-mission SAM relocation, or scale the mission up for a larger flight.

I’ve built a first version of the Liberation-style campaign tool, packaged as iron_anvil_campaign.zip. It’s a small slice of what Liberation does, not a replacement. I couldn’t run DCS here, so it hasn’t been flown yet. I did generate missions, reload them with pydcs, and run the mission Lua against a mock of the DCS API (full win path, Kutaisi captured, Senaki generated next). Expect the first real launch to need a small fix.

How it works

It keeps the war state in a campaign.json file and builds a new .miz for each sortie with pydcs, the same library Liberation uses.
A small hook script in Saved Games\DCS\Scripts\Hooks writes the results while you fly, so no MissionScripting.lua edits are needed.
The debrief command reads those results back, so what you destroy stays destroyed.
What’s in this version

Persistence: damage is tracked per unit, and destroyed depots show up as wrecks in later missions.
Campaign: four red bases (Kutaisi, Senaki, Sukhumi, Gudauta) against Batumi and Kobuleti. A base flips to blue once its command post is dead and it’s mostly destroyed, and you then fly from the captured airfield.
Economy: red rebuilds one damaged asset per turn, and its fighter pool shrinks when you shoot CAP down.
Each sortie: a SEAD and strike on one base for two Hornet client slots. It comes with a tanker, an AWACS, a random time of day and wind, and red fighters launching 4 to 15 minutes in.
Loadout: 2 HARM, 4 JDAM, 2 AMRAAM, 2 AIM-9X and a centre tank, set explicitly. The F10 menu has the same BRA, smoke and vector-home tools as the earlier script.
To run it

Run pip install -r requirements.txt.
Run python -m ironanvil install-hook.
Run python -m ironanvil new, then generate.
Fly the mission, then run debrief.
The README has the full workflow and the options (autoresolve skips a turn without flying).

What it doesn’t do yet

There’s no GUI.
There are no blue AI packages, red retaliation strikes or front lines.
There’s only one theatre, Caucasus.
Site positions are offsets from each airfield, so a few may land on awkward terrain. They’re easy to move in theatre.py.
Wait about a minute after the “State saved” message before exiting, because the hook polls every 10 seconds.
Check dcs.log for lines starting IRON ANVIL if something doesn’t trigger.

The GUI is added to iron_anvil_campaign.zip. Unzip it and double-click run_gui.pyw, or run python -m ironanvil gui. It uses Tkinter, which comes with the standard Windows Python installer, so there’s nothing extra to install.

I ran it headless under a virtual display and checked screenshots. Generating a mission, picking up a debrief, applying it, capturing a base, and auto-resolve all worked from the interface. I haven’t run it on real Windows or inside DCS.

What you get

Map: the theatre is drawn from real airfield positions. Click a red base to target it, and the nearest blue base is picked as your launch point (click a blue base to override).
Base status: small boxes under each red base show command post, ammo, fuel, SAM and AAA health, and a ring shows its overall strength. Captured bases turn blue.
Mission planner:
time of day (random, dawn, day, dusk, night)
red air defence (none, light, auto, heavy)
loadout (SEAD + strike, heavy strike with 2000-lb JDAMs, SEAD only)
a tanker and AWACS toggle
Target intel: a panel lists the selected base’s defences and their health.
After the flight: the GUI notices the debrief file on its own and shows a summary (units destroyed, aircraft lost, result). Press Apply debrief to roll the turn. If you want to skip flying a turn, there’s an Auto-resolve button.
DCS setup: Browse sets your Saved Games folder, Install hook copies the debrief hook, and Open missions folder jumps to where the .miz files land.
Generation runs in the background so the window doesn’t freeze. All the new planner options also work from the command line engine, and the README now covers both ways of running it.

Two things to know. If you capture bases out of order, the auto-picked launch base is simply the closest blue one, so check it before generating. Also, the first launch needs the DCS folder and hook set up once, and you should restart DCS after installing the hook.
