# Iron Anvil Experimental 1.4.2 — native enemy CAP launch and confirmation

Addresses reports that **enemy fighters were enabled but no CAP appeared**. The supplied mission contains two staged MiG-29s, valid waypoint time locks and the correct CAP setting. Launch depended entirely on the Lua controller; it treated a successful activation API call as proof that fighters had spawned, even when no active aircraft could be confirmed. Without a simulator log, the exact reason the reported DCS activation failed cannot be established here.

## What's changed

- **Native DCS CAP launch.** Every client slot has a built-in mission trigger. Once any client climbs above **30 m / about 100 ft above the ground**, DCS activates the configured enemy flights directly by group ID. This works independently of the mission controller's takeoff event, group lookup and activation API call. Cold-start preparation remains unopposed by these staged fighters.
- **Actual spawn confirmation.** CAP is announced as active only after the controller sees living aircraft with DCS `isActive()` true. Inactive templates do not count as spawned fighters or defeated CAP.
- **Limited recovery attempts.** The native launch has a 45-second grace period after client takeoff. If fighters are still unconfirmed, the controller makes at most three activation requests, 15 seconds apart, using the documented activation APIs. Confirmed flights are never reactivated or respawned after destruction. Delayed native activation can still be recognized after retries stop.
- **Visible CAP status in every mission type.** F10 → Iron Anvil → Mission status reports waiting, pending, confirmed active fighters or an unconfirmed launch. Failed requests produce named CAP diagnostics in `dcs.log`. Briefings explain when fighters launch.
- **Correct life boundary.** A DCS unit with one remaining life point is still alive. It no longer disappears from client polling or CAP counts solely because its life equals one.
- **Saved-trigger and runtime regression checks.** Tests execute the native launch code from real generated archives for all three maps, cold/air starts and multiple enemy flights, with the main controller and script activation API absent. They cover a second client taking off, parked/unused slots, one-shot launch, silent API failure, delayed spawn, bounded retries, both activation APIs and partial activation without respawns. The compiled Windows probe also checks every mission's native launch links against its actual client and enemy IDs.

The earlier tanker/AWACS/CAP waypoint timing fix is retained. The enemy CAP checkbox still disables all enemy fighter groups and launch triggers. No extra controls, mods, Python installation or scripting-security changes are needed.
